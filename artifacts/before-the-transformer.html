Before the Transformer: what to carry from Bengio to LayerNorm

Seven papers, grouped by idea instead of by year. Each tab: what to remember, with our own numbers as evidence, and questions to answer while reading Attention Is All You Need (2017). The Mechanics part has the equations, shapes and backward pass of every block, each with a hand check.

Is 2017 the start of the current era?

Yes for the architecture. The recipe comes in the next three years.

Almost every major model after 2017 is a Transformer, so this paper starts the current architecture. The current era also needs two ideas still ahead on the reading list: pretraining on unlabelled text and then reusing the model (GPT-1, BERT, 2018), and scale (GPT-2, GPT-3, scaling laws).

Each paper so far fixed one bottleneck and exposed the next. The Transformer is easiest to understand as the answer to the bottlenecks still open in 2016.

Representation

What a token is, and what its vector knows

Every model so far starts the same way: split text into symbols, look each one up in a table, and predict symbols at the output. The choices that matter are the vocabulary, what trains the vectors, and how expensive the output layer is.

An embedding lookup is a one-hot row times a matrix

C[idx] equals one_hot(idx) @ C. So the gradient only reaches the rows that were looked up in that batch, and a row that is never used never moves.

OursIn CBOW, a word's own input vector is updated only when it appears as a context word, which under-serves named entities. That is the live explanation for the Word2Vec entity gap.

Meaning comes from predicting context

Words that predict similar neighbours end up with similar vectors, and a dot product scores how well two vectors match. Bengio, C&W, Word2Vec and GloVe all train vectors this way; they differ in the objective and in cost.

OursA falling loss is not proof of good vectors: our GloVe loss fell while directions barely moved from their random start.

Static vectors have one meaning per word

Word2Vec and GloVe give "bank" one vector. In our project, the Bi-RNN encoder in Bahdanau was the first place where a word's vector depended on its sentence: h_j has read both sides.

The output layer is the expensive part

Scoring every word costs |V| × h per position. In Bengio's model that is 99.7% of compute. Hierarchical softmax and negative sampling existed to avoid it.

OursNegative sampling did not beat hierarchical softmax at text8 scale (14.2% vs 14.8%), unlike the paper's +12.

Vocabulary trades UNK against sequence length

Words give short sequences and many <UNK>. Characters give no <UNK> and 4.65x longer sequences. BPE sits in between: 1.08x the length and no <UNK>, with a 30k vocabulary.

OursThe word-level model emits <UNK> for 15.6% of its tokens (beam), though only 6.1% of the reference needs it.

Input and output can share one space

Bengio's energy variant embeds the candidate output word with the same matrix C as the input. That is the idea behind tying input and output embeddings.

Context and memory

The key quantity is path length between two tokens

A fixed window cannot see far. A recurrent network can, in principle, but information and gradients have to travel through every step in between. Most of what broke so far is explained by how long that path is.

An RNN is one cell applied T times

The same W_xh and W_hh are used at every step, so their gradient is a sum over steps. The gradient from step T to step 1 multiplies T-1 Jacobians diag(f') W_hhᵀ, so it vanishes or explodes.

The fixed-vector bottleneck is a learning problem, not a storage problem

A sentence of 50 tokens from a 100-word vocabulary is about 330 bits, which fits easily in 512 floats. The vector could hold the sentence; training does not learn to put it there, because the path from the first word to the last output is too long.

OursNo-attention baseline at length 46-50: 0.224 token accuracy (H=64), 0.258 even with 11.6x the parameters. Low on the train set too, so it is not memorization.

Attention made one path short

With attention, every source position is one step away from every decoder step. The encoder itself is still a chain: source word 1 reaches source word 50 through 49 recurrent steps.

The encoder may look both ways; the decoder may not

A Bi-RNN encoder lets h_j see the whole sentence. The decoder cannot: at test time the future does not exist yet, and at training time seeing it would let the model copy the answer.

Recurrence is sequential compute

Step t needs h_(t-1), so positions cannot run in parallel. Only the batch dimension parallelizes.

OursRNNsearch-50 at paper size: 0.615 s per step on a T4, about 25 hours for 7 epochs on 1.65M pairs.

Padding needs masks everywhere

Padded positions must not leak: -inf before the attention softmax, frozen or packed RNN states, and the backward RNN must start at the real end of each sentence.

The mechanism that survives

Query, key, value were already in Bahdanau

The Transformer keeps attention and removes almost everything around it. So the most useful preparation is to know exactly what each part of our Bahdanau attention does, and which part is doing the real work.

Three roles

Query: the decoder state before the step, s_(i-1). Keys: U_a h_j, computed once per sentence. Values: the encoder states h_j. Score each key, softmax over source positions, take the weighted sum of values.

Additive vs dot-product scores

Bahdanau: v_aᵀ tanh(W_a s + U_a h). Dot product with projections: (s W_Q) · (h W_K). The projections matter in both: they let the query and key live in a search space separate from the raw memory, and they fix any size mismatch. The dot product is one batched matrix multiply.

Shapes to know by heart

Query (B, 1, A) broadcast against keys (B, T, A); scores (B, T); softmax over T (dim 1); context bmm(α.unsqueeze(1), H) gives (B, 1, 2H), then .squeeze(1) gives (B, 2H). A fully masked row gives NaN.

Attention is sharp only where the output needs the source

OursToy heatmap: 0.98-0.99 on the right source word for every word. The <eos> row put only 0.04-0.49 on source <eos>: the decoder state already knew when to stop, so the loss never forced it to look.

One query, one weighted average

A single softmax gives one mixture of the source per decoder step. If a word needs two pieces of information from different places, one softmax has to compromise between them.

Can a deep stack train?

Gradients multiply through depth; normalization keeps the scale in range

An RNN is deep in time. A Transformer is deep in layers. The same tools explain both: the backprop shape rules, the product of Jacobians, and normalization that resets the scale at every step.

Backprop through a linear layer

Y = X W + b gives dW = Xᵀ dY, dX = dY Wᵀ, db = dY.sum(0). A gradient always has the shape of the thing it belongs to; the transposes come from that.

Used N times forward, summed N times backward

A broadcast bias, a shared RNN weight, an embedding row used twice in a batch: each use sends back its own gradient, and they add.

BatchNorm couples examples

It normalizes each neuron across the batch. So it needs running statistics for test time, padding in one sentence corrupts the statistics for all, a batch of 1 breaks it, and in an RNN it would need separate statistics per time step.

LayerNorm normalizes each example on its own

μ, σ per example over its H features, shape (B, 1); learned gain and bias per feature, shape (H,). Same formula at train and test. It is invariant to scaling the whole weight matrix or one input example, but not to scaling a single neuron's weights. BatchNorm is also invariant to the whole matrix, and the reverse on the other two: it is about rows vs columns of (B, H).

Ours||dL/dh_0|| over 50 steps at weight scales 0.25 / 1 / 2.5: vanilla 0 / 1.9e-15 / 1.5e-5, LayerNorm 2.868e-11 at all three. On a memory task the vanilla RNN stayed at MSE 3.98 while the LayerNorm RNN reached 0.19.

Still open in the backprop playbook

Elementwise nonlinearity, softmax + cross-entropy (p - y), deep chains and singular values, initialization as variance preservation, BPTT, BatchNorm and LayerNorm backward. Worth finishing the softmax and initialization steps before the Transformer's attention math.

Habits that saved or cost days

Most wrong conclusions came from the experiment, not the model

These lessons are paper-independent. Each one is backed by a run where it mattered.

Check the batch averaging before copying a learning rate

A per-example rate under a batch-mean loss is effectively divided by the batch size.

OursC&W: 0.01-0.1 proposed, 1.0 needed. Word2Vec: 0.025 at B=256 behaved like 0.025/256, with no learning in 10,000 steps.

Short sweeps pick unstable rates

The large steps that win early are the ones that diverge later. Probe stability over a long stretch and watch weight norms. Abort on "absurd", not on "non-finite": a diverging loss stays finite for a long time.

OursWord2Vec: a 1,000-step sweep ranked lr 2 as 2.7x better than lr 1; lr 2 diverged early in the epoch, lr 1 finished cleanly.

Undertrained is not the same as worse

Compare models at their plateau, and quote the noise band, not one lucky checkpoint.

OursToy baseline at 10 epochs looked hopeless everywhere; it needed ~150 epochs (attention: 9). Its best checkpoint, val loss 1.0, was a dip inside a 1.1-1.2 noise band.

Change one thing, and read results per bucket

Match the baseline on everything except the idea being tested (our attention vs no-attention: params within 2%). Then split the metric: averages hide where a model fails, and train vs val per bucket separates "cannot learn" from "memorizes".

OursWord2Vec's skip-gram lead is entirely in named entities. The H=256 baseline memorizes lengths 21-40 and cannot fit 41-50 even on train.

Gate with a toy, cross-check implementations

A task with a known answer (reversal, anti-diagonal attention) catches wiring bugs before an expensive run. Two implementations checked with allclose (packed GRU vs masked loop) catch subtle ones.

One run shows a direction, not a result

Every comparison here is one seed. Short probes mislead too: a 1M-step Word2Vec probe showed a +0.4 gap where the full epoch showed +5.4 on the same comparison.

Long runs need a headless script

Checkpoint and resume by experiment name, keep the run out of a live notebook kernel, load your own caches with weights_only=False, and write files atomically when an editor has them open.

From model to number

How you decode and score can move results more than the model

Beam search added more BLEU than BPE did. Pitfalls in BLEU scoring changed scores silently. A number only means something with its decoding and scoring setup next to it.

Teacher forcing vs free running

Training feeds the true previous token; decoding feeds the model's own guess. The model is never trained on its own mistakes, so one bad token can derail the rest.

OursGreedy word-level output has <UNK> runs averaging 2.67 against 1.08 in the reference, and one run of 160 that never stopped.

Beam search is free BLEU

Keep K hypotheses, freeze the finished ones, pick by score divided by length. Raw log-probability favours short outputs, so some length correction is needed.

OursBeam 12 adds +3.5 BLEU to both word-level (15.23 → 18.76) and BPE (16.11 → 19.62). The BPE gap stays ~0.9.

Losses in different units do not compare

Perplexity is exp(mean cross-entropy) per token, so it depends on what a token is. BPE val loss is per subword, word-level per word: compare them by BLEU only.

BLEU is easy to get subtly wrong

Score against the original reference tokens (reference ids turn rare words into <UNK> that then match), do not tokenize twice, cut at EOS. The n-gram breakdown shows where a gain sits.

OursBPE's gain is mostly unigram precision (+3.6 greedy). Reference from ids inflated BLEU; a lost tokenize="none" changed it.

Test the paper's own claim

A proxy metric can pass while the claim stays untested. GloVe was closed without its analogy test, so it is not a reproduction. BPE's real claim is about rare and unseen words: its unigram F1 is still open.

Conventions and the four backward rules

Same conventions as our notebooks: batch first, rows are examples, right multiplication Y = X W with W of shape (in, out). Every block on the next tabs is written as a forward table, a backward table, a hand check, and what to notice.

The four backward rules

  1. Shape rule. A gradient has the shape of its tensor. For Y = X W: dW = Xᵀ dY, dX = dY Wᵀ. The transposes are forced by the shapes.
  2. Elementwise rule. For u = f(a) (a = pre-activation, u = output): da = du ⊙ f'(a). Written with the output: tanh' = 1 - u², sigmoid' = u(1 - u); ReLU' = 1[a > 0].
  3. Fan-out rule. A tensor used k times forward gets k gradients backward, and they add. Shared RNN weights, an embedding row used twice, c_i going into both the GRU and the output.
  4. Broadcast rule. A broadcast forward is a copy, so backward sums over the broadcast axis: db = dY.sum(0); the attention query (B, 1, A) sums over T.

How to dry-run any model

  1. Write every forward tensor with its shape, in order.
  2. Mark what backward will need: each op's inputs and outputs (activations). This is what memory holds during training.
  3. Start from dlogits and walk the list in reverse, one op at a time.
  4. After each step, check the gradient's shape against its tensor. A wrong shape is almost always a missing transpose or a missing sum.
  5. Verify on tiny sizes with autograd, or with a finite difference (L(θ+ε) - L(θ-ε)) / 2ε.

Mechanics · 2003-2014

Bengio's MLP, C&W, Word2Vec and GloVe, forward and backward

Four ways to train word vectors. The interesting part is where the gradient for each word vector comes from, and what the output layer costs.

NoticeThere is no V-way output at all: the cost of one update does not depend on the vocabulary size. And once the real window wins by a margin of 1, the pair stops sending gradient.

Skip-gram with negative sampling

vectorsv_c = V_in[center], u_o = V_out[context], u_k for each of the m sampled negatives (u here is an output vector, not a tanh output)
lossL = -log σ(u_o·v_c) - Σ_k log σ(-u_k·v_c)
dv_c(σ(u_o·v_c) - 1) u_o + Σ_k σ(u_k·v_c) u_k
du_o(σ(u_o·v_c) - 1) v_c
du_kσ(u_k·v_c) v_c
NoticeEach term is (prediction - label) times the other vector, the same pattern as softmax + CE, but for m+1 binary classifiers instead of one V-way softmax. Hierarchical softmax is the same binary classifier at each of ~log₂V tree nodes.

CBOW: the average splits the gradient

v = (1/n) Σ_j V_in[ctx_j], then the same output head with v in place of v_c. Backward: dv is the dv_c formula from the card on the left, and each context word's row gets dv / n.

NoticeThe centre word's input vector is never updated when it is the centre; it only moves when it appears as someone else's context. That is the live hypothesis for CBOW losing on named entities.

Mechanics · recurrence

RNN step, BPTT, and the GRU's extra path

Backprop through time is ordinary backprop on the unrolled graph. Two things make it special: the same weights are used at every step (sum their gradients), and the gradient to early steps passes through a product of Jacobians.

Vanilla RNN

forward, step tequationshape
pre-activationa_t = x_t W_xh + h_(t-1) W_hh + b(B, H)
stateh_t = tanh(a_t)(B, H)
outputo_t = h_t W_hy + b_y, then softmax + CE per step(B, V)
backward, t = T down to 1equationshape
startdh_next = 0 at t = T; do_t = (p_t - onehot(y_t)) / N from M2
dW_hy, db_y+= h_tᵀ do_t, += do_t.sum(0)(H, V), (V,)
dh_tdo_t W_hyᵀ + dh_next (from the output and from step t+1)(B, H)
da_tdh_t ⊙ (1 - h_t²)(B, H)
dW_xh, dW_hh, db+= x_tᵀ da_t, += h_(t-1)ᵀ da_t, += da_t.sum(0)(D, H), (H, H), (H,)
dx_t, dh_nextda_t W_xhᵀ, da_t W_hhᵀ; after t = 1, dh_next is dh_0(B, D), (B, H)
NoticeFrom step T back to step 1 the gradient is multiplied T-1 times by diag(1 - h²) W_hhᵀ. If that factor is below 1 in size it vanishes, above 1 it explodes. This is the long path from tab 3.
Hand check: H = 1, W_xh = 1, W_hh = 0.5, h_0 = 0, x = [1, 1], L = h_2 
h_1 = tanh(1)                = 0.7616
h_2 = tanh(1 + 0.5 · 0.7616)   = 0.8811
da_2 = 1 · (1 - 0.8811²)       = 0.2236
dh_1 = da_2 · W_hh             = 0.1118
da_1 = 0.1118 · (1 - 0.7616²)  = 0.0470
dW_xh = x_1 da_1 + x_2 da_2     = 0.2706
dW_hh = h_0 da_1 + h_1 da_2     = 0.1703

GRU, paper form (the Bahdanau paper adds c_i to each gate)

z  = σ(x W_z + h U_z + c C_z)          update gate
r  = σ(x W_r + h U_r + c C_r)          reset gate
h̃  = tanh(x W + (r ⊙ h) U + c C)      candidate
h' = (1 - z) ⊙ h + z ⊙ h̃
Notice∂h'/∂h contains the term (1 - z) with no weight matrix and no tanh. Where z ≈ 0, the gradient passes through unchanged. Gates add a path around the multiplication.
Backward, paper form (given dh') 
dh̃ = dh' ⊙ z        dz = dh' ⊙ (h̃ - h)      dh = dh' ⊙ (1 - z)
da_h̃ = dh̃ ⊙ (1 - h̃²)   da_z = dz ⊙ z(1 - z)
d(r⊙h) = da_h̃ Uᵀ     dr = d(r⊙h) ⊙ h      dh += d(r⊙h) ⊙ r
da_r = dr ⊙ r(1 - r)
dh += da_z U_zᵀ + da_r U_rᵀ
dx  = da_z W_zᵀ + da_r W_rᵀ + da_h̃ Wᵀ     (same pattern with C_* for dc)
dW_* = xᵀ da_*   dU_z = hᵀ da_z   dU_r = hᵀ da_r   dU = (r⊙h)ᵀ da_h̃

PyTorch's nn.GRU differs in two places

It writes h' = (1 - z) ⊙ n + z ⊙ h, so z plays the opposite role. And its candidate applies r after the matmul: n = tanh(x W_in + r ⊙ (h W_hn + b_hn)). Gates are packed as (r, z, n).

These are the traps we hit when cross-checking the masked-loop encoder against packed nn.GRU. Our decoder uses nn.GRUCell on the input [E y ; c], so this is the form to dry-run for our model.

r  = σ(x W_ir + b_ir + h W_hr + b_hr)
z  = σ(x W_iz + b_iz + h W_hz + b_hz)
n  = tanh(x W_in + b_in + r ⊙ (h W_hn + b_hn))
h' = (1 - z) ⊙ n + z ⊙ h
Backward, PyTorch form (given dh') 
dn = dh' ⊙ (1 - z)     dz = dh' ⊙ (h - n)     dh = dh' ⊙ z
da_n = dn ⊙ (1 - n²)    da_z = dz ⊙ z(1 - z)
dr = da_n ⊙ (h W_hn + b_hn)     da_r = dr ⊙ r(1 - r)
d(h W_hn) = da_n ⊙ r
dh += d(h W_hn) W_hnᵀ + da_z W_hzᵀ + da_r W_hrᵀ
dx  = da_n W_inᵀ + da_z W_izᵀ + da_r W_irᵀ
dW_i* = xᵀ da_*    dW_hn = hᵀ (da_n ⊙ r)    dW_hz = hᵀ da_z    dW_hr = hᵀ da_r
Hand check: H = D = 1, every weight 1, biases 0, x = 1, h = 0.5, dh' = 1 
r = z = σ(1.5) = 0.8176     n = tanh(1 + 0.8176·0.5) = 0.8872
h' = 0.1824·0.8872 + 0.8176·0.5 = 0.5706
dn = 0.1824   dz = 0.5 - 0.8872 = -0.3872
da_n = 0.0388   da_z = -0.0578   dr = 0.0194   da_r = 0.0029
dh = 0.8176 + 0.0388·0.8176 - 0.0578 + 0.0029 = 0.7945
dx = 0.0388 - 0.0578 + 0.0029 = -0.0160

dh is dominated by the direct z path (0.8176); all the gated paths together add only -0.0231. That is the gate's shortcut.

Bahdanau attention, forward and backward with shapes

Mechanics · normalization

LayerNorm forward and backward, and why the scale cancels

LayerNorm takes statistics over the features of one example (each row). BatchNorm uses the same formulas over the batch (each column).

forwardequationshape
mean, varianceμ = mean_H(x), var = mean_H((x - μ)²), with keepdim(B, 1)
normalizestd = √(var + ε), x̂ = (x - μ) / std(B, 1), (B, H)
scale, shifty = x̂ ⊙ g + b, with g, b of shape (H,)(B, H)
backwardequationshape
dg, db(dy ⊙ x̂).sum(0), dy.sum(0)(H,)
dx̂dy ⊙ g(B, H)
dx(1/std) · (dx̂ - mean_H(dx̂) - x̂ ⊙ mean_H(dx̂ ⊙ x̂)), each mean_H of shape (B, 1)(B, H)
NoticeEach row of dx sums to 0 and is orthogonal to x̂, so the gradient never changes the mean or the overall scale of the input. Scaling x by λ leaves x̂ the same and divides dx by λ. That 1/std is why our gradient stayed at 2.868e-11 at every weight scale.
Hand check: x = [1, 2, 6], g = 1, b = 0, ε = 0, dy = [1, 0, 0] 
μ = 3     var = (4 + 1 + 9) / 3 = 4.6667     std = 2.1602
x̂  = [-0.9258, -0.4629, 1.3887]
dx = [0.1763, -0.2204, 0.0441]    (sum 0, dx·x̂ = 0)
x × 10 -> same x̂, dx = [0.0176, -0.0220, 0.0044]

Edge case: with H = 2 and ε = 0, x̂ is always [-1, 1] or [1, -1], so dx = 0. LayerNorm needs enough features to be useful.

BatchNorm, the same formulas over the other axis

μ, std per feature over the batch, shape (1, H); running averages are kept for test time. In the backward, mean_B replaces mean_H, so example 1's gradient depends on example 2's values.

What each one is invariant to

Both are invariant to scaling the whole weight matrix. LayerNorm is also invariant to scaling one training example, but not to scaling one neuron's weight vector. BatchNorm is the opposite on those two. (Ba et al. 2016, Table 1.)

Mechanics · algorithms around the model

Greedy, beam search, BPE and BLEU, step by step

None of these have gradients, but each one changed our numbers. These are the versions in our notebooks.

Greedy decode

y = [SOS] * B ; finished = [False] * B
for step in range(max_len):
    logits, s = decoder(y, s, ...)
    y = argmax(logits)            # (B,)
    y[finished] = PAD
    finished |= (y == EOS)
    if all(finished): break
# then cut each row at its first EOS

Beam search, batched (our version)

repeat encoder outputs K times     # row b*K + k
scores = [0, -inf, ..., -inf] per sentence
for step in range(max_len):
    logp = log_softmax(decoder(...))       # (B*K, V)
    logp[finished] = -inf ; logp[finished, PAD] = 0
    cand = (scores + logp).view(B, K*V)
    scores, idx = cand.topk(K)
    parent, token = idx // V, idx % V
    reorder s, history, finished by parent
    if all finished: break
best = argmax(scores / lengths)

BPE, learn and apply

learn:  words as chars + </w>, weighted by count
        repeat N times: merge the most frequent
        adjacent pair, record it
apply:  rank = {pair: position in merge list}
        repeat: among the word's pairs, merge the
        one with the lowest rank; stop when none
        of its pairs has a rank

Worked example and Table 1 are in the BPE artifact.

BLEU

p_n  = clipped n-gram matches / n-grams in output
BP   = 1 if c > r else exp(1 - r / c)
BLEU = BP · exp( (1/4) Σ_(n=1..4) log p_n )
Hand check: word greedy, p = 42.2 / 19.4 / 10.7 / 6.1 %, BP = 1 
(0.422 · 0.194 · 0.107 · 0.061)^(1/4) = 0.152
BLEU ≈ 15.2   (reported 15.23 from unrounded p_n)
NoticeBLEU is a geometric mean: a weak 4-gram precision pulls the whole score down. Clipping stops an output from scoring by repeating one matching word.
